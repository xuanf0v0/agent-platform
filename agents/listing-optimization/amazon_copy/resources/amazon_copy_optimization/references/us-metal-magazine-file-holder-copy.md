# US Metal Magazine File Holder Copy

Use this reference for US desktop metal magazine file holders, binder organizers, vertical file organizers, and closely related compartment racks.

## Product-fact gate

Verify before drafting:

- Saleable child vs parent ASIN and selected compartment count/color.
- Exact dimensions and orientation (`D x W x H`).
- Metal mesh/frame construction.
- Number of compartments.
- Label holders/slots and anti-slip feet.
- Assembly requirement and included setup materials.
- If the user confirms printed instructions but no video, state only `includes printed instructions`; remove every installation-video reference inherited from old copy.
- Do not import a competitor's compartment count, dimensions, weight, finish, or included parts.

## Competitor-language handling

A direct competitor title/PDP can establish market-language evidence such as:

- `magazine file holder`
- `binder organizer`
- `desk file organizer`
- `metal desk organizer`
- `vertical file organizer`
- `desktop organizer`
- `label slots`
- `space-saving desktop storage`

This is not proof of search volume, ABA rank, or traffic contribution. Label it as public competitor wording unless SellerSprite/SIF/SQP evidence is available.

## Related-ASIN differentiation

When the user optimizes two or more metal file organizers in sequence, compare the newly requested SKU against the previously finalized one before drafting:

- Build a mini matrix for compartment/slot count, total width, compact vs wide form factor, label/foot design, assembly, and primary stored objects.
- Do not recycle one title pattern such as `N Vertical Compartments Magazine File Holder, Metal Binder Organizer, Black` and change only `N` when the sibling differs structurally.
- Give each structurally different SKU a distinct verified lead: a compact 4-compartment model may emphasize `Magazine File Holder` and space-saving desktop storage; a wider 5-slot Plus model may emphasize `Desk File Organizer`, verified width, and binder/folder access.
- Differentiate Item Highlights as well as titles. Shift the feature/benefit emphasis instead of repeating the same comma-separated phrases.
- Keep differences factual. Never create artificial uniqueness with unsupported claims such as `oversized`, `heavy duty`, `large capacity`, or `fully assembled`.

### Simple color siblings under a short-title cap

When the next request is the same construction in another color:

- Still open the sibling child separately and verify its ASIN, parent ASIN, color, material, dimensions, and compartment count; do not infer the child solely from the prior variant.
- Preserve the approved core-keyword order across color siblings unless the sibling has a real structural difference. A pure color variant should remain recognizably parallel to the approved family wording.
- Under the requested `≤75-character` title format, prioritize: brand → strongest exact product phrase → verified natural-position phrase → child color. Add material or compartment count only if it fits naturally.
- If exact keyword phrases plus the child color consume the title budget, move the verified compartment count into Item Highlights rather than replacing a proven exact phrase with a weaker synonym such as `slot` merely to save characters.
- Use Item Highlights to recover complementary facts omitted from the title: material/frame, compartment count, access benefit, stored objects, and representative office/school/classroom contexts.
- Do not repeat the color in Item Highlights when the title already identifies it, unless color itself is a purchase benefit. Keep Title and Item Highlights semantically complementary.
- Deterministically verify title and Item Highlights character counts and exact-token repetition before delivery.

## Bullet allocation pattern

Use one keyword family and one purchase intent per bullet:

1. Compartment organization: `binder organizer`, `folder organizer`, compatible materials.
2. Footprint/scenarios: `desk file organizer`, exact dimensions, office/classroom/study use.
3. Material/stability: `metal desk organizer`, metal mesh, qualified anti-slip benefit.
4. Sorting/access: `vertical file organizer`, label holder, project/subject/document classification.
5. Setup/secondary use: `magazine file holder`, `desktop organizer`, printed assembly instructions when verified.

Keep subheadings short—normally 2–4 words, for example:

- `4-Compartment Storage`
- `Desk File Organizer`
- `Metal Mesh Frame`
- `Labeled File Sorting`
- `Easy Assembly`

Do not make subheadings long keyword sentences. Put secondary keywords naturally in the body.

## Backend Search Terms

- Stay within 249 UTF-8 bytes when using the team's upload target.
- Use lowercase, spaces only, no brands, ASINs, promotions, or competitor identifiers.
- Avoid wasting bytes on exact phrases already fully covered in the title.
- Avoid duplicate tokens where possible; use complementary roots for objects, scenarios, audiences, and synonyms.
- Count characters/bytes deterministically before delivery.

Example structure only—adapt to verified facts and title coverage:

`desk desktop document folder rack sorter office supplies storage classroom workspace home mail notebook textbook literature paper study teacher student school catalog manual upright tabletop labels 3 ring workstation homeschool records portfolios`

## Final checks

- Child title matches actual compartment count and color.
- Title/Item Highlights/bullets do not repeat the same full phrases unnecessarily.
- Bullet bodies contain keywords naturally and remain readable on mobile.
- No unsupported durability, stability, capacity, efficiency, or included-component claim.
- Every corrected product fact is propagated through all fields.
