# US Wall File Organizer Short Fields

Use this reference for US metal wall file organizers, hanging file holders, wall-mounted mail sorters, and tier/count variants.

## Product-identity gate

Before drafting, verify the selected child and record:

- tier/pocket count;
- single pack vs multi-pack;
- wall-only vs wall/desktop dual use;
- included base;
- hooks or no hooks;
- open compartments/pockets;
- label holders/panels;
- metal/mesh construction;
- selected color;
- dimensions when independently exposed on the selected child.

Never inherit `with Base`, `with Hooks`, tier count, or pack count from a sibling. A family can contain visually similar wall-only, desktop/wall dual-use, hook-equipped, and multi-pack children.

## Short-title allocation

When the active user format omits brand and favors denser keyword coverage, use:

`[Tier Count] + Wall File Organizer + Hanging File Holder + Distinct Verified Search Phrase`

Useful verified phrase families include:

- `wall file organizer`
- `hanging file organizer`
- `hanging file holder`
- `wall mounted file holder`
- `mail organizer wall mounted`
- `wall mail organizer`
- `document organizer`
- `paper sorter` / `mail sorter` when the product genuinely sorts those items

Keep one SKU-defining fact in the title (`with Base`, `with Hooks`, pack count) when it affects the purchase decision. Do not use `with Base` for a wall-only child or `with Hooks` when the selected child lacks hooks. Under the user's current short-title workflow, keep Title at ≤75 characters and ensure no exact word appears more than twice.

## Item Highlights

Item Highlights should complement, not restate, the title. Good new-information buckets are:

- metal mesh construction;
- open compartments/pockets;
- label holders/panels;
- stored objects such as mail, folders, papers, magazines, notebooks, or clipboards;
- 2–3 representative contexts such as home, office, school, or classroom.

When the user requests title-style capitalization, capitalize meaningful words but keep ordinary connectors lowercase: `with`, `and`, `for`, `at`, `or`, `in`, `a`, `the`. Keep the field ≤125 characters and count it deterministically.

## Backend Search Terms

Finalize Title and Item Highlights first, then rebuild Search Terms from missing relevant roots. Remove exact visible-field tokens and duplicates. Useful secondary roots may include:

`vertical rack pocket filing bill letter notebook book clipboard classroom school cubicle workspace inbox correspondence brochure receipt portfolio chart form stationery storage wire`

Only use roots relevant to the selected child. No brands, ASINs, punctuation stuffing, promotions, unsupported load/size claims, or sibling-only features.

## Claim guardrails

Do not use these without independent support:

- `heavy duty` or load-capacity claims;
- `rustproof`, `waterproof`, or absolute oxidation claims;
- `no drill` or universal wall compatibility;
- `legal size`, `letter size`, or A4 compatibility without usable pocket dimensions;
- hooks, base, mounting method, or included hardware copied from another child.

Amazon autocomplete and repeated competitor wording are market-language evidence only. They do not prove search volume, rank, conversion, or keyword priority.
